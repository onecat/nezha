## Handling interruption

A grant is single-use; a missing response does not authorize installation. If the Agent already consumed the sequence, it durably records failure. When a grant was never committed, the Dashboard can acknowledge the exact authenticated failed reservation after a complete delivery/verification, including a task already failed by expiry. The reservation receipt and sequence floor are committed atomically with terminal state. No success or rollback is accepted without an actual grant. If a grant was committed but the reply was lost, the normal granted-failure receipt path applies. Both paths accept exact retries; do not reissue an installation grant. The local ledger remains authoritative.

To stop new operations without rejecting existing terminal receipts, retain valid enabled provisioning and set allow_execution=false, then restart Dashboard. New HTTP admissions and grants are disabled. Previously queued downloads can still be staged/verified but cannot obtain an install grant. Already granted local operations may finish or roll back. Keep server identity and key provisioning until outstanding results are acknowledged. Fully disabling provisioning removes the RPC path, so receipt delivery must wait for restored provisioning. Do not infer that an unreported granted task failed merely because it expired. Late success and irreconcilable state still require operator review; do not modify the database or reset the Agent ledger to clear a warning.

## Release boundary

Use only artifacts from a green paired run, verify the source hashes and SHA256SUMS, and follow the included Linux deployment document. The two positive version binaries are built from the same candidate source with different version labels; they are not separately published releases. Keep the signing private key offline. The new Agent is a monitoring and managed-upgrade implementation, not a complete legacy replacement. Existing terminal/tunnel/command/service-monitor task use must remain on the legacy Agent until qualified. Windows managed updates are deferred. The same-host TLS proxy is the qualified topology. Production deployment, formal release and operator reconciliation of remaining ambiguous cases are not automated.
