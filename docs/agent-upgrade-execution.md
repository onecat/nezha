# Development execution grant and result

Separate Grant and Result RPC methods require an explicit additional execution gate (default false). Grant rechecks original operator approval, platform eligibility and signed package, then atomically records the installing state and grant audit before replying. Grant is single-use: a lost reply must not lead to automatic installation. Result accepts the exact authenticated task with an existing grant, persists terminal Agent claims and audit in a single SQLite transaction, and allows exact duplicate receipts. The server records the remote terminal observation directly rather than pretending to have observed intermediate local health states. A late successful result is refused pending reconciliation; late rollback/failure remains acceptable. A missing result remains reserved. The Agent is responsible for actual process-bound health proof; this is not independent remote attestation.

The production registration remains disabled; trusted live eligibility, operator web API, durable server high-water tracking, recovery reconciliation and full Dashboard/Agent integration remain outstanding. Tests exercise local database and grant/result rules, not production deployment.
