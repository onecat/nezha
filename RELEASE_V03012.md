# Dashboard v0.30.12

Agent and Dashboard release versions are decoupled. In Settings > Agent installation, a local superadmin in TLS automatic upgrade mode explicitly enters a versioned raw Linux amd64 binary URL from the independent onecat/nezha-agent repository. Dashboard checks SHA256SUMS, binary bytes, ELF static dependencies and Go build identity/platform before saving the URL, version, checksum and revision in SQLite. No compiled-in Agent URL/digest, no background latest lookup or automatic upgrades. First use requires saving the desired release, including after upgrading from .11. The same persisted pin drives installation and confirmed upgrades; stale confirmations and modified release bytes fail closed. Invalid selections leave the previous setting intact.

The separate upgrade-status button and URL prompt are removed in automatic mode. Select up to three servers, preview the saved version and eligible/skipped targets, confirm, and see live results in the server page. Manual signed-package mode and internal status/reconciliation APIs are retained. Existing same-version reinstalls preserve the ledger; a different installed version must use an authorized forward upgrade first, never a silent downgrade. No Agent release changes; .04 is only a regression fixture in CI. Linux amd64 validation, real install/reinstall, restart persistence, direct update and failed-exec rollback remain release gates.
